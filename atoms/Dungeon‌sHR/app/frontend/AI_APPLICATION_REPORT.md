# 《地下城打工人 Dungeon HR》AI 应用报告

---

## 1. AI 应用场景总览

本项目在以下场景中使用了 AI 技术：

| 场景 | AI 模型/工具 | 用途 |
|------|-------------|------|
| 代码生成与架构设计 | Claude / GPT 系列 LLM | 全栈代码编写、系统架构设计、游戏引擎逻辑、UI 组件开发 |
| 代码调试与优化 | Claude / GPT 系列 LLM | Bug 定位与修复、性能优化、代码重构 |
| 音乐生成 | lyria-3-pro-preview | 4 首结局专属 BGM（胜利/苦涩/荒凉/灾难风格） |
| 产品设计与需求分析 | LLM 辅助 | PRD 文档生成、游戏数值平衡设计、事件文案撰写 |
| 文案创作 | LLM | 游戏内事件卡片文案、怪物名称池、幽默对话、触发剧情文本 |

> **注**：游戏美术资产（角色立绘、背景、UI 素材等）均为用户提供的原创手绘素材，未使用 AI 图像生成。

---

## 2. 作品关键 AI 应用阐述

### 2.1 AI 驱动的全栈游戏开发

整个游戏从零开始由 AI 辅助完成，包括：
- **架构设计**：类型系统（types.ts）、数据层（data.ts）、引擎层（engine.ts）、状态管理（useGame.ts）、UI 组件层的分层架构
- **游戏逻辑**：战斗演算引擎、勇者 AI 行为树（觉醒/友谊/道具/策反/必杀技/复活 6 大机制）、经济系统、招募系统、转职系统
- **迭代优化**：经历 v0.1 → v0.33 共 30+ 次迭代，每次迭代由 AI 完成需求理解→代码修改→lint/build 验证的完整闭环

### 2.2 AI 音乐生成

使用 Google 的 **lyria-3-pro-preview** 模型生成 4 首结局 BGM：
- E01（完美结局）：凯旋风格，大气磅礴
- E02（普通结局）：苦涩甜蜜，略带遗憾
- E03（失败结局）：荒凉萧瑟
- E04（破产结局）：灾难性、压迫感

### 2.3 AI 辅助游戏设计

- 数值平衡：怪物三职业（TANK/DPS/RANGE）属性模板、勇者分级（W01-ELITE）数值曲线
- 事件系统：17+ 战斗事件 + 8 个日常事件的文案与效果设计
- 词条系统：10+ 怪物词条的创意设计与数值效果

## 3. 费用明细表（积分消耗估算）

| 消耗类别 | 占比（估） | 说明 |
|----------|-----------|------|
| LLM 代码生成（主要） | ~85% | 30+ 次版本迭代，每次涉及多文件读写、逻辑推理、代码生成。使用 Claude/GPT 高级模型进行复杂游戏逻辑开发 |
| LLM 需求分析与设计 | ~8% | PRD 生成、架构设计、数值平衡讨论、Bug 分析 |
| 音乐生成 | ~5% | 4 首 BGM（lyria-3-pro-preview），每首约 15-30 秒循环片段 |
| 其他（搜索/工具调用） | ~2% | 文件读写、终端命令、构建验证等辅助操作 |

### 主要积分流向：
1. **代码开发**（最大头）：游戏引擎、状态管理、UI 组件、弹窗系统等约 5000+ 行 TypeScript 代码的生成与迭代
2. **调试修复**：图像映射、存档兼容、事件触发等 10+ 个 Bug 的定位与修复
3. **UI 重构**：经历 15+ 次 UI 调整（从 CSS 装饰 → 全图片背景 → 布局对齐 → 按钮一致性）
4. **音乐生成**：4 首结局 BGM 的生成
