## 1. 一句话 Pitch & 核心循环

### Pitch 🟢

> 你是魔王城新上任的 HR 总监。勇者定期突袭，你需要招募怪物、管好薪酬、抵御每一波冲击，撑过 N 波让魔王城成功上市。

### 核心循环 🟢

```
[准备阶段]  行动点 = AP_MAX，玩家循环操作直到 AP=0：
  ├─ 招募    ：消耗 1 AP，从 3 份 AI 生成简历中选 1 入职（招募免费，仅锁日薪）
  ├─ 扩建    ：消耗 1 AP，花费 SHARDS_BUILD 增加怪物槽位
  ├─ 发奖金  ：消耗 1 AP，花费 SHARDS_BONUS 给指定怪物本场战力增益
  └─ 打零工  ：消耗 1 AP，自动获得 AP_TO_SHARD_RATE × 1 = 4 灵魂碎片（HR 跑外勤报销，v0.2 新增）
       ↓
[战斗阶段]  自动推进，逐 ROUND_TICK 演算
  └─ 期间触发突发事件 → 暂停 → 10s 内二选一 → 继续
       ↓
[绩效考评] 战后处理：
  ├─ 阵亡怪物：扣抚恤金（薪水 × 3 + 5）
  ├─ 表现差：玩家可主动解雇
  ├─ 存活且达成升级条件：自动升级（属性提升）
  ├─ 升级后随机怪物可能发起谈薪 → 玩家二选一
  └─ 通关绩效提成自动入账（公式 §3 RewardOnClear，v0.2 新增）
       ↓
循环回 [准备阶段]，下一波勇者突袭
```

### 胜负条件 🟢

| 结果 | 条件 | 触发点 |
|------|------|--------|
| 赢 | 撑过 N 波勇者突袭 | T07 → E01 / E02 |
| 输① | 某波战斗后怪物全部阵亡或离职 | T08 → E03 |
| 输② | 灵魂碎片归零且无法支付下一日薪水 | T09 → E04 |

## 2. 顶层游戏状态机

```
GameState 枚举：
  GAME_INIT          ─→ MAIN_PREP
  MAIN_PREP          ─→ BATTLE_START (玩家点"开战")
  BATTLE_START       ─→ ROUND_TICK
  ROUND_TICK         ─→ ROUND_TICK / EVENT_TRIGGER / BATTLE_END
  EVENT_TRIGGER      ─→ ROUND_TICK (玩家做出选择或超时)
  BATTLE_END         ─→ EVAL
  EVAL               ─→ MAIN_PREP (下一关) / GAME_OVER (失败) / ENDING (胜利)
  ENDING             ─→ (终态，播放结局演出)
  GAME_OVER          ─→ (终态)
```

### 子状态机：MAIN_PREP

```
ENTRY (设 AP = AP_MAX, refresh 简历池)
  ↓
WAITING_INPUT  ←─────────────────┐
  ↓ (玩家点动作)                    │
  ├─ RECRUIT_DIALOG  → 选完 → AP--─┘  (v0.7 招募免费，恢复 v0.2 规则)
  ├─ BUILD_DIALOG    → 完成 → AP--─┘
  ├─ BONUS_DIALOG    → 完成 → AP--─┘
  ├─ LABOR_CONFIRM   → 确认 → AP-- + SHARDS += 4 ─┘  (v0.2 新增 / "打零工")
  └─ START_BATTLE    → exit MAIN_PREP
  ↓ (AP == 0 时 START_BATTLE 自动可点亮)
```

### 子状态机：BATTLE

详见第 5 节。

### 子状态机：EVAL

```
ENTRY (本波结束)
  ↓
CASUALTY_REPORT (T05 触发条件)
  ↓ (玩家点继续)
PERFORMANCE_LIST (列出所有怪物本场表现 - DPS/受伤/词条触发)
  ↓ (玩家可点解雇按钮)
DISMISS_DIALOG (可选)
  ↓
LEVEL_UP_PHASE (检查升级条件)
  ↓
NEGOTIATE_PHASE (P02 触发条件)
  ↓
P03/P05_CHECK (经济警告)
  ↓
EXIT → MAIN_PREP (下一关)
```

## 5. 战斗系统

### 顶层流程 🟢

```
BATTLE_START
  ├─ 隐藏词条激活（首次出战的怪物）
  ├─ 战斗日志首条 "[T03 文案] 突袭警报…"
  ↓
ROUND_TICK (循环)
  │  双方各攻击一次：怪物 ATK_sum vs 勇者 ATK
  │  HP 更新 → 输出 1 条战斗日志
  │  默认推进时长 1.2 ~ 1.5s（玩家点击可立即跳到下一条）
  │  检查：是否触发突发事件？(本场已触发数 < 3 且本回合命中触发条件)
  ↓ (触发)
EVENT_TRIGGER
  │  暂停战斗，全屏卡片弹出
  │  10s 倒计时（圆环 UI），玩家二选一
  │  超时 → 默认选不利选项（每个事件预定义不利项）
  │  应用效果 → 返回 ROUND_TICK
  ↓
检查 BATTLE_END 条件：
  ├─ 勇者 HP ≤ 0           → 我方胜
  ├─ 我方全员 HP ≤ 0        → 我方败（T08）
```

### 战斗演算 🟢（balance v0.2.0 §2.1 已落地）

> 公式权威以 balance §2.1 为准，下面是 Atoms 落码视角的伪代码。

```
每个 ROUND_TICK：
  对怪物方每只存活怪物 m 与勇者 H：
    monsterDamage_m = Damage(m, H, modifiers)   // 单只伤害走 BalanceFormula.Damage
  totalMonsterDamage = Σ monsterDamage_m × random(0.9, 1.1)
  heroDamage         = Damage(H, monsterTeam, modifiers) × random(0.9, 1.1)
  
  HERO.HP -= totalMonsterDamage
  分配 heroDamage 到怪物队（按 HP 比例，MVP 取此简化版）
  
  伤害公式（balance §2.1）：
    base       = attacker.ATK × (1 + modifiers.atkBonus)
    isMiss     = rand() < BASE_MISS_RATE       // 0.05（balance）
    if isMiss: damage = 0
    else:
      isCrit   = rand() < attacker.CRIT_RATE   // 模板默认：TANK 0.03 / DPS 0.08 / RANGE 0.10；勇者 0.00–0.18 见 §6
      critMul  = isCrit ? 1.5 : 1.0            // CRIT_MULTIPLIER（balance）
      damage   = floor(base × critMul × mitigation)   // mitigation 默认 1.0，预留接口
    
    // 若 attacker == HERO 且 isCrit && 本场未触发过暴击：
    //   发出 OnFirstHeroCrit 事件 → 触发 B07
```

### 战斗日志文案生成器 🟢

> 系统每个 ROUND_TICK 输出 1 条战斗日志，文案从模板池中随机抽取，填入怪物/勇者 ID 与伤害值。

模板示例（每类 5-8 条，MVP 期间可压缩到每类 3 条）：

| 模板类 | 示例 |
|--------|------|
| 怪物攻击命中 | "[怪物名] 发起反击，造成 X 点伤害。" |
| 勇者攻击命中 | "勇者挥剑而下，[怪物名] 承受 X 点伤害。" |
| 怪物 Miss | "[怪物名] 试图反击，但勇者闪过。" |
| 勇者 Miss | "勇者一击落空，[怪物名] 险险闪过。" |
| 暴击 | "[攻击方] 抓住破绽，[防守方] 承受 X 点暴击伤害！" |
| 阵亡 | "[怪物名] 力竭倒下。HR 系统记录在案。" |

### 突发事件触发判定 🟢

```
每场战斗最多触发 3 个突发事件。
每个 ROUND_TICK 结束后：
  如果 本场已触发数 < MAX_EVENTS (= 3)：
    遍历本关事件池中**未触发过**的事件
    检查每个事件的 trigger_condition 是否满足
    如果有多个同时满足：取触发优先级最高的（按 ID 升序）
    应用 trigger_probability（部分事件是必触，部分是概率）
```
