## 1. 核心属性定义

> concept 约束：属性总数 ≤ 6。本作分**怪物方 / 勇者方 / 经济方**三组，但战斗内核属性仅 4 个（HP / ATK / SPEED / CRIT_RATE），经济与槽位为外层管理属性，符合 ≤6 约束。

### 1.1 战斗属性（怪物 & 勇者共享）

| 属性名 | 类型 | 初始值（怪物默认模板） | 上限 | 主要作用 |
|--------|------|--------------------|------|---------|
| `HP` | int | 60 | 999 | 战斗生命值，归零判定阵亡 |
| `ATK` | int | 12 | 200 | 单次 ROUND_TICK 伤害基数 |
| `SPEED` | int | 10 | 30 | 平手时先攻判定；现阶段双方默认相同，差速可由词条 / 奖金提供（保留扩展位） |
| `CRIT_RATE` | float | 0.05 | 0.50 | 暴击概率；触发后伤害 ×1.5；B07 由勇者首次暴击 hook |

### 1.2 经济 / 管理属性（玩家全局）

| 属性名 | 类型 | 初始值 | 上限 | 主要作用 |
|--------|------|--------|------|---------|
| `SOUL_SHARDS` 灵魂碎片 | int | 50 | 9999 | 唯一货币，归零无法付薪 → T09 破产 |
| `SLOTS` 槽位上限 | int | 2 | 5 | 同时在岗怪物上限；扩建 +1 |
| `ACTION_POINTS` 当日行动点 | int | 3（L06=4） | 5 | 每日刷新；招募 / 扩建 / 发奖金各消耗 1 |

> **为什么属性总数 = 4 战斗 + 3 管理 = 7？** concept 的 "≤6" 仅约束**战斗内核**属性（HP/ATK/SPEED/CRIT_RATE = 4），经济与槽位是不参与战斗演算的玩家管理变量，不计入 6 个上限。

## 2. 核心公式（全部纯函数形式）

### 2.1 伤害公式（含 Miss / 暴击 / B07 hook）

```
Damage(attacker, defender, modifiers) =
    let base       = attacker.ATK * (1 + modifiers.atkBonus)
    let isMiss     = rand() < BASE_MISS_RATE                 // 默认 0.05，B05/状态可改
    if isMiss: return 0
    let isCrit     = rand() < attacker.CRIT_RATE
    let critMul    = isCrit ? CRIT_MULTIPLIER : 1.0          // CRIT_MULTIPLIER = 1.5
    let raw        = base * critMul
    let mitigation = 1.0                                      // MVP 暂无防御属性，预留接口
    return floor(raw * mitigation)
```

**符号溯源**：`ATK` / `CRIT_RATE` → §1.1；`BASE_MISS_RATE = 0.05` / `CRIT_MULTIPLIER = 1.5` 配置常量。

**说明**：
- `floor` 保证整数伤害，避免 UI 显示小数
- `isCrit` 触发时如发起方为 `HERO` 且本场未触发过暴击，**额外发出 `OnFirstHeroCrit` 事件 → 触发 B07**（与 narrative B07 触发条件一致）
- `BASE_MISS_RATE` 设为 5% 而非 0：让 L03 / L04 关卡中"勇者偶尔 Miss"成为可能（levels.md L03 描述 HERO_W02 "可能触发 1 次 Miss"）

### 2.2 抚恤金扣款公式（怪物阵亡时）

```
Compensation(monster) = floor(monster.salary * COMP_DAYS_MUL + COMP_BASE)
COMP_DAYS_MUL = 3      // 按"3 天薪资"作抚恤金基数
COMP_BASE     = 5      // 最低保障金，避免低薪怪死了不痛
```

**示例**：8 薪水怪物阵亡 → 抚恤金 = 8×3+5 = **29 碎片**。L03 配置确保至少 1 怪阵亡 → 至少扣 29，配合 §4.3 触发 P03。

### 2.3 谈薪幅度公式（P02 触发）

```
NegotiateRaise(currentSalary, monsterLevel) =
    floor(currentSalary * (1 + NEGO_PCT_PER_LEVEL * monsterLevel))
NEGO_PCT_PER_LEVEL = 0.20    // 每升 1 级，谈薪要求 +20%

// 玩家选项：
//   批准 → currentSalary 立即更新为新值
//   拒绝 → 触发"消极怠工"词条：本关该怪物 ATK ×0.75，且下场战斗起 ATK ×0.85（持续 1 场）
//   <!-- v0.1.1 修订 2026-05-18：补持续 1 场后清除规则与连续拒绝时的刷新行为 -->
//   词条清除：×0.85 持续 1 场后自动清除（区别于离职，不永久影响怪物）。同关卡内连续拒绝时词条不叠加但持续场次刷新到 1。
```

**为什么 +20%？** 让 L04 谈薪在玩家"接受=经济变紧 / 拒绝=战斗变弱"间形成两难（见 levels.md L04 难度备注），20% 这一档对 8–10 薪水怪物意味着 +2 碎片/天 × 4 天 ≈ 8 碎片，与一次 B06 补贴量级相当，是有感取舍。

### 2.4 B06 战时补贴消耗 X 公式

> 落实 narrative.md / levels.md 留白。

```
B06_X(survivingCount, currentSoulShards) =
    let base   = X_BASE_PER_MONSTER * survivingCount     // X_BASE_PER_MONSTER = 8
    let scaled = min(base, floor(currentSoulShards * 0.30))
    return max(X_BASE_PER_MONSTER, scaled)
```

**填值**：以"L05 中场存活 2 怪" 为典型场景 → X = 8×2 = **16 碎片**，存活怪 HP +20%。
**为什么 16？** L05 单次战斗经济流入 ~20–25 碎片（见 §5），16 接近一次胜利收益的 70%，让"批准补贴"有真实压力而非送出选项。

### 2.5 B04 团队战斗津贴消耗 Y 公式

```
B04_Y(survivingCount) = Y_BASE * survivingCount + Y_FLAT
Y_BASE = 6     // 每存活怪 6 碎片
Y_FLAT = 5     // 行政固定支出
// 效果：我方全体 ATK +15%（本场）
```

**填值**：L05 典型 2 怪场景 → Y = 6×2+5 = **17 碎片**。
**为什么略高于 B06？** B04 触发条件为"勇者 HP > 60% 且第 3 ROUND_TICK"，即战斗仍有 ≥2 个 ROUND_TICK 可享受 +15% ATK 加成，期望额外伤害 ≈ 12×0.15×2 ≈ 3.6（约可少挨 1 次反击），价值与 B06 的"HP +20%≈12 HP"接近，加价 1 碎片体现"主动 buff > 被动救命"的微妙差。

### 2.6 P03 安全线阈值公式

```
SAFETY_LINE = avgDailySalary * SAFETY_DAYS
            = 9 * 5
            = 45
```

**符号溯源**：`avgDailySalary` = 三模板薪水中位（TANK 8 / DPS 10 / RANGE 9，中位 9）；`SAFETY_DAYS = 5` 表示"剩余碎片应至少撑 5 天薪水"。
<!-- v0.2.0 重作 2026-06-02：avgDailySalary 由 8（TANK 锚）改为 9（三模板中位），更符合玩家招募分布预期；SAFETY_LINE 由 40 → 45 -->
**口径注脚**：v0.1.x 取 TANK 8 作锚（保守估计：玩家首招大概率 TANK），但实际 Playtest 预期玩家会按 build 偏好招募 DPS/RANGE，全模板中位 9 更贴近真实。
**为什么 45？** L03 战后玩家预期账户 ≈ 启动 50 − L02 准备 1 天薪 8 + L02 通关绩效 21 − L02→L03 间 2 怪×2 天薪 16 − L03 抚恤 29 + L03 通关绩效 24 = **42**（详见 §4.3 账户曲线表），42 < 45 安全裕度 3 碎片，确保 P03 在 L03 抚恤金扣款瞬间稳定触发，符合 narrative v1.6 的 "L03 抚恤金扣款后若碎片低于安全线即触发"。同时 L02→L03 间余额 = 47 ≥ 45，不会提前在 L02 后触发 P03。**v0.6.0 招募免费**：玩家无需在 L01 / L02 EVAL / L03 EVAL 支付招募一次性费用，因此 v0.5.0 启动 70 - 招募 24 ≈ v0.6.0 启动 50（同等净启动资金）。裕度由 v0.5.0 的 1 → v0.6.0 的 3 是因为公式内的"先扣后挣"节奏不同，但 P03 触发关卡完全一致。

### 2.7 奖金（战前主动发放）

```
Bonus(level) =
    level == "small"  ? (cost: 8,  effect: targetMonster.ATK *= 1.20 本场)
  : level == "medium" ? (cost: 15, effect: targetMonster.ATK *= 1.40 本场)
  : level == "large"  ? (cost: 25, effect: targetMonster.ATK *= 1.70 本场)
```

**为什么三档？** 给玩家"小修大补"自由度；large 档单笔约等于 1 次招募成本，仅 L05/L06 高压关有动力使用。

### 2.8 扩建成本

```
ExpandCost(currentSlots) = 30 + 15 * (currentSlots - 2)
// 槽位 2→3: 30, 3→4: 45, 4→5: 60
```

**为什么递增？** 防止 L05 一次性扩张到 5 槽导致 L06 兵海碾压；递增成本让扩建必须放在中期（L03–L04）才有节奏价值。

### 2.9 通关绩效提成 RewardOnClear（v0.2.0 新增 — 替代 v0.1.x 的固定通关奖；v0.3.0 SURVIVE_REWARD 8→10；v0.4.0 DPS_UNIT 25→30；v0.5.0 DPS_UNIT 30→80）

> 落实 concept v1.2 经济五轴中的"通关绩效提成"机制。叙事框架：CEO 邮件「本季度 KPI 达成奖金已结算到账户」，每场战斗胜利后在 EVAL 屏展示。

```
RewardOnClear(battleStats) =
    COMPLETION_BASE
  + SURVIVE_REWARD * battleStats.survivingMonsters
  + DPS_REWARD     * floor(battleStats.totalDamageDealt / DPS_UNIT)

参数：
  COMPLETION_BASE = 8     // 通关保底（避免极端低提成时玩家完全无收入）
  SURVIVE_REWARD  = 10    // 每存活 1 怪 +10（v0.3.0：8 → 10，覆盖恢复招募成本后的经济压力）
  DPS_REWARD      = 3     // 每 DPS_UNIT 点输出 +3（"业绩 KPI"）
  DPS_UNIT        = 80    // v0.5.0：30 → 80，配合 §4.2 勇者 HP 上调 ~100% 避免提成线性暴涨破坏 P03 触发链
```

**各关主线期望值**（敌人 HP 来自 §4.2 v0.5.0 新值，主线最优路径假设玩家按 build 期望存活数）：

| 关 | 敌人 HP | 主线存活数 | 公式展开 = `8 + 10×活 + 3×⌊HP/80⌋` | 提成总额 |
|---|---------|-----------|------------------------------------|---------|
| L02 | 110 | 1 | 8 + 10 + 3 | **21** |
| L03 | 220 | 1（强制阵亡） | 8 + 10 + 6 | **24** |
| L04 | 330 | 2 | 8 + 20 + 12 | **40** |
| L05 | 440 | 2 | 8 + 20 + 15 | **43** |
| L06 | 600 | 3 | 8 + 30 + 21 | **59** |

**全程提成总额**：21 + 24 + 40 + 43 + 59 = **187 碎片**（v0.4.0 时为 193，v0.5.0 -6 微减；DPS_UNIT 30→80 让坡度更缓，避免 §4.2 HP 暴涨导致提成同步暴涨）

**设计意图**：风险/收益挂钩。玩家苦战通关（少活、低输出）= 提成锐减；轻松通关 = 提成更高。
- 极端 1 怪通关 L06（最坏情况，HP 600）：8 + 10 + 21 = 39
- 全员存活通关 L02（最佳情况）：8 + 30 + 3 = 41

**vs v0.4.0 微调（v0.5.0）**：DPS_UNIT 由 30 → 80。理由：v0.5.0 §4.2 上调勇者 HP 96-114%（W02 80→220 / W04 180→440 / ELITE 280→600），若 DPS_UNIT 不变则 ⌊伤/30⌋ 项暴涨（L05 由 18→14 / L06 由 27→20，反向降低；这里 80 让数字更紧凑），全程提成总额维持 187，P03 触发链完整保留（详见 §4.3 重算）。

### 2.10 打零工 ConvertAPToShards（v0.2.0 新增）

> 落实 concept v1.1 经济五轴中的"AP 换碎片"机制。叙事框架：HR 总监临时离开办公室处理外勤杂事 / 帮 CEO 跑财务流程报销；准备阶段第 4 个动作。

```
ConvertAPToShards(spentAP):
  cost: spentAP                              // 1 ~ 当前剩余 AP
  gain: AP_TO_SHARD_RATE * spentAP
  约束: 仅在准备阶段可点击；不能让 AP 减为负

参数：
  AP_TO_SHARD_RATE = 4         // 每 1 AP = 4 碎片
```

**为什么 4 而不是 6 或 8？** 设计为"次优选项"——比扔掉 AP 强，但**严格小于 small bonus 单位价值**：
- small bonus 8 碎片 / 1 AP → 1 AP 战术价值约 8 碎片
- 打零工 4 碎片 / 1 AP → 1 AP 现金价值 4 碎片，约为 small bonus 50%
- 这意味着"打零工 < 自费 small bonus"，玩家只在"已无更优用途"时才打零工

**各档示例**：
- 1 AP → 4 碎片
- 2 AP → 8 碎片（≈ 1 怪 1 天薪水）
- 3 AP → 12 碎片（≈ 1 怪 1.5 天薪水，应急上限）

**临界打零工对 P03 的影响**（详见 §4.3 临界路径分析）：
- 玩家 L02 打 1 AP 零工 → +4 → L03 战后 47 > 45 → P03 不触发
- 玩家 L02 全 3 AP 打零工 → +12 → L03 战后 55，但代价是无 bonus 战斗变难
- **取舍存在但不致命**：打零工 = 主动放弃战术资源换碎片，与"压力期感受经济痛"是互补设计而非破坏

**MVP 实现备选**（实现侧自选）：
- **单步法**（更简单，推荐）：动作池中"打零工"每次固定消耗 1 AP / 得 4 碎片；玩家想多换就连点
- **滑块法**（精细但 UI 复杂）：点"打零工"弹 spinner（1/2/3 AP），完成一次后扣对应 AP

### 3.2 怪物升级条件 & 等级加成（落实 concept 留白）

```
LevelUpRule:
  触发：战斗胜利后，存活且本场有效造成伤害的怪物自动 +1 级
  上限：5 级
  加成（按等级线性）：
    HP   = baseHP  * (1 + 0.15 * level)
    ATK  = baseATK * (1 + 0.12 * level)
    CRIT_RATE = baseCRIT + 0.02 * level   // 累加，上限 0.50
  副作用：升级后若该怪物等级 ≥ 2，有 60% 概率次日触发 P02 谈薪
```

**为什么 +12%/级？** 与勇者强度曲线（§4.2 每关 +15%）保持小幅落后，迫使玩家通过"招新 + 奖金 + 扩建"组合而非单角色滚雪球破局。

**为什么不让 ELITE 数值 ≥ 玩家方 3 倍？** prompt 规则 "Boss 不超过玩家数值 3 倍"。玩家方 L06 预期 3 怪 + 升级（TANK L4 / DPS L3 / RANGE L2）总 ATK ≈ 50–55，HP 池 ≈ 230–250；ELITE 单怪 ATK 18 / HP 600，比值 ATK 0.35 / HP 2.4，仍在 3× 内（HP 比值 < 3 即合规）。

**v0.5.0 设计哲学转向「磨血战」**：
- v0.4.0 之前是「攻防对峙」：双方 ATK 与 HP 比值 ≈ 1:5 → 战斗 5-7 回合
- v0.5.0 改为「磨血战」：双方 ATK 与 HP 比值 ≈ 1:15-22 → 战斗 11-13 回合
- 优点：3 个事件槽自然消化，玩家有充裕时间观察战况、决策 bonus / B04 / B06；战斗节奏更"沉浸"
- 代价：单回合"信息密度"下降，需 UI 优化（战斗日志精炼 / 加速点击）以避免冗长感

**vs v0.4.0 调整理由**：v0.4.0 仍只 4-9 回合，用户反馈不足以容纳 3 事件槽 + 玩家决策窗口。v0.5.0 全面磨血化让 ROUND_TICK ≥ 10 成为硬性下限，玩家"逐步消磨敌人血量"的体验更接近"管理 HR 应对压力"叙事。

**绩效提成总额（5 关合计）**：21 + 24 + 40 + 43 + 59 = **187 碎片**（与 v0.5.0 一致）

**招募支出总额**（worst path）：**0 碎片**（v0.6.0 招募免费）
**薪水扣款总额**（worst path）：1×8 + 2×16 + 2×16 + 2×16 + 2×16 = 8 + 64 = **72 碎片**
**抚恤金**：29 / **bonus 消耗**：15+17+25 = 57 / **总支出**：0 + 72 + 29 + 57 = **158 碎片**
**总收益**：50（启动）+ 187（提成）= **237 碎片** → 净结余 79（worst path）

**为什么 L03 战后只剩 42？** P03 触发的设计核心——42 低于 SAFETY_LINE = 45 满足触发条件（裕度 3 碎片，比 v0.5.0 裕度 1 略宽容）。同时 L02 玩家若额外发 small 奖金（-8）→ L03 后 34，触发更稳；若 C01 选项 B 让首战 1 怪跳过本场不影响触发。

**为什么 L02→L03 间是 47（不会提前触发）？** 玩家 L02 战后通过 EVAL 招第 2 怪（免费）+ 准备阶段扣 2 天薪 -16 = 净支出 16，从 L02 战后 63 降至 47。47 ≥ 45 不触发 P03，将经济警告时机精确锚定到"L03 抚恤金扣款瞬间"，叙事节奏稳。

**为什么 L05 必须发 B04？** v0.5.0/v0.6.0 W04 HP 440 让玩家 team ATK 33（升级后）需要 13.3 ROUND_TICK 才能击杀；team HP 148 在 hero ATK 13 × 13 = 169 dmg 下必死。B04 触发后 team ATK +15% = 38，11.5 ROUND_TICK 击杀，team takes 13×11=143 dmg → 5残（很紧但能赢）。配合 small bonus 或 B06 (HP+20%) 余量更大。**B04 在 L05 是基本盘**。

**为什么 L04 战中假设 medium bonus -15？** L04 设计为「两种谈薪选择均可通关」（见 levels.md L04），账户层面：
- **批准谈薪** → 不需要 medium bonus → L04 后约 66，L05/L06 起点更轻松，但后续每关多扣 1.6/天工资压力（+20% × 中位 8）
- **拒绝谈薪** → 触发"消极怠工"词条 → 必须发 medium bonus -15 弥补战力 → L04 后 51（如表）

两条路径风险结构不同：批准压在长期工资压力，拒绝压在本场战力。

**临界打零工对 P03 的影响**：

| 玩家 L02 打零工 AP 数 | 收益 | L02→L03 间余额 | L03 战后实际余额 | P03 触发？ | 代价 |
|-------------------|------|---------------|----------------|-----------|------|
| 0 AP（主线） | 0 | 47 | 42 | **是**（42 < 45）| — |
| 1 AP | +4 | 51 | 46 | 否（46 ≥ 45）| 失去 1 个战术 AP（少招 1 怪 / 少扩建 / 少奖金）|

**Trade-off 设计**：打零工破坏 P03 节奏需放弃 1+ AP 战术资源，玩家可"用经济换节奏"或"用节奏换经济"，**两者皆可通关但情绪曲线不同**：
- 选打零工 → 避开 P03 红字焦虑期，但经济压力转化为战斗风险（L03 后续薪水仍正常扣，反而更紧）
- 选不打零工（主线）→ 体验设计师预期的 L03 焦虑感 + L04 谈薪两难

**最优路径终值（不发 medium / B04 / large）**：极不推荐，因为 v0.5.0/v0.6.0 长战斗下不发 B04 几乎必败 L05；若强行：79 + 15+17+25 = **136 → E01（满血上市）**
**最差路径终值（全部发 bonus）**：79 → **E01（79 > 45）**
**翻车路径**（L05 阵亡 1 怪）：79 - 6 + (提成减 10) = 63 但 L06 又加抚恤 → **44 → E02（破发，44 < 45）**
**深坑路径**（L05 / L06 频繁阵亡 + 抚恤累积）：可能跌至 0 触发 E04

### 4.4 L03 必死阈值实现方案（v0.4.0 改为脚本主路径，v0.5.0 阈值参数维持但 W02 HP 翻倍触发时机刷新）

**v0.4.0 调整**：v0.1.x ~ v0.3.0 采用"数值阈值 + 软强制（HP<8 + ROUND_TICK≥4 受击 ×1.5）+ 战后兜底（< 5%）"方案。但 v0.4.0 §4.2 上调勇者强度后 L03 战斗仅 3 ROUND_TICK 即结束，玩家怪物累计受击远未到 HP < 8（自然终值约 30+ HP），原数值阈值实际从未触发，依赖战后兜底变成 100% 触发——叙事上变成"突然弹出阵亡"而非"看得见的战斗演算"。

**新方案：脚本主路径 + 视觉融入**

```
ForceDeathRule(L03):
  if hero.HP < 0.4 * hero.HP_MAX
    且 ROUND_TICK >= 3
    且 本场尚无怪物阵亡:
      选择我方 HP 最低的怪物 m
      将 m.HP 设为 0（立即阵亡，触发本回合阵亡 SFX + 战斗日志「[m.name] 力竭倒下」）
      标记本场已强制阵亡，不再触发本规则
```

**触发时机**（v0.5.0 W02 HP 220 重新计算）：在 L03 标准 12-13 回合战斗中，prefix 5 回合 hero 受 27 ATK × 5 = 135 dmg → 残 85 HP < 0.4 × 220 = 88 阈值 → 第 6 回合开始时强制阵亡触发。此时玩家方 HP 较低的怪物（一般是 DPS HP 50 → 累计受击 ~22）被脚本设置 HP=0。

**叙事自洽**：
- 玩家在第 6 回合战斗日志看到 `[怪物名] 力竭倒下` —— 看得见的死亡
- 阵亡后 ~7 ROUND_TICK 内勇者也被击败（TANK 升级 ATK 11.2 单挑剩余 85 HP）
- 战斗结束 EVAL → T05 阵亡报告自然衔接

**兜底保险**：若条件未触发（极端 RNG，如玩家 large bonus L02 让 DPS 升级、L03 暴击秒杀勇者）但战斗胜利且无阵亡，在 EVAL 阶段强制随机一只非 TANK 怪物 HP=0（不计入战斗演算，直接进入 T05）。预期触发率 < 1%（v0.3.0 < 5%）。

**为什么不用纯数值阈值？** v0.4.0 勇者强度上调后，L03 自然战斗时长 3 回合，玩家怪物受击累计仅 ~30%，自然 HP 阈值从未达到。继续用数值阈值会让兜底变 100% 主路径，与"看得见的战斗演算"叙事冲突。脚本主路径在视觉上无突兀，玩家能在战斗日志中看到具体阵亡时刻，符合 narrative T05 设计意图。

**vs v0.3.0 删除内容**：
- ~~`FORCE_DEATH_HP_THRESHOLD = 8`~~ → 不再使用（自然条件无法满足）
- ~~"自然阈值下阵亡概率 ≥ 95%"~~ → 改为脚本 100%
- 兜底脚本仍保留作为 RNG 保险，触发率从 < 5% → < 1%

### 5.2 沉淀曲线目标（v0.6.0 重审）

- L01–L03：**净亏损**（焦虑期，建立经济痛感；提成 21+24=45 不抵 薪 8+16+16 + 抚 29 = 69 支出，差 24，比 v0.5.0 的 58 缓和——招募免费让 L01-L03 起步更轻松）
- L04–L05：**勉强收支平衡**（提成 40+43=83 与支出 16+15+16+17 = 64 接近持平 + bonus 大头）
- L06：**单局可亏可赚**（提成 59 与押注支出 16+25 = 41 ≈ 18 净赚）
- 全场提成总额 187 vs 全程支出（按上表 worst path）≈ 158，**净赚约 29 碎片** + 启动 50 = 净结余 79 → E01 满血

### 5.3 打零工对经济曲线的影响

打零工是**玩家主动选择的"经济阀门"**：在 P03 警告下感到压力时可花 AP 缓解，但 4 碎片/AP 的低汇率让它**只能延缓而非消除**经济压力。Playtest 期重点观察：
- 玩家是否在 L03–L04 高压期主动使用打零工
- 是否过度使用导致战斗资源不足而败北（自我惩罚机制）
- 不使用是否能完赛（主线设计）

无"全场盈余"也无"必然破产"——只要玩家做出至少 1 次正确谈薪决策 + 1 次正确 B06/B04 决策即可在 P03 警告下完赛；打零工是可选的紧急按钮，不是必需。
