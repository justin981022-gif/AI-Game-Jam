## 1. 核心属性定义

> concept 约束：属性总数 ≤ 6。本作分**怪物方 / 勇者方 / 经济方**三组，但战斗内核属性仅 4 个（HP / ATK / SPEED / CRIT_RATE），经济与槽位为外层管理属性，符合 ≤6 约束。

### 1.1 战斗属性（怪物 & 勇者共享）

| 属性名 | 类型 | 初始值（怪物默认模板） | 上限 | 主要作用 |
|--------|------|--------------------|------|---------|
| `HP` | int | 60 | 999 | 战斗生命值，归零判定阵亡 |
| `ATK` | int | 12 | 200 | 单次 ROUND_TICK 伤害基数 |
| `SPEED` | int | 10 | 30 | 平手时先攻判定；现阶段双方默认相同，差速可由词条 / 奖金提供（保留扩展位） |
| `CRIT_RATE` | float | 0.05 | 0.50 | 暴击概率；触发后伤害 ×1.5；B07 由勇者首次暴击 hook |

### 1.2 经济 / 管理属性（玩家全局）

| 属性名 | 类型 | 初始值 | 上限 | 主要作用 |
|--------|------|--------|------|---------|
| `SOUL_SHARDS` 灵魂碎片 | int | 120 | 9999 | 唯一货币，归零无法付薪 → T09 破产 |
| `SLOTS` 槽位上限 | int | 2 | 5 | 同时在岗怪物上限；扩建 +1 |
| `ACTION_POINTS` 当日行动点 | int | 3（L06=4） | 5 | 每日刷新；招募 / 扩建 / 发奖金各消耗 1 |

> **为什么属性总数 = 4 战斗 + 3 管理 = 7？** concept 的 "≤6" 仅约束**战斗内核**属性（HP/ATK/SPEED/CRIT_RATE = 4），经济与槽位是不参与战斗演算的玩家管理变量，不计入 6 个上限。

## 2. 核心公式（全部纯函数形式）

### 2.1 伤害公式（含 Miss / 暴击 / B07 hook）

```
Damage(attacker, defender, modifiers) =
    let base       = attacker.ATK * (1 + modifiers.atkBonus)
    let isMiss     = rand() < BASE_MISS_RATE                 // 默认 0.05，B05/状态可改
    if isMiss: return 0
    let isCrit     = rand() < attacker.CRIT_RATE
    let critMul    = isCrit ? CRIT_MULTIPLIER : 1.0          // CRIT_MULTIPLIER = 1.5
    let raw        = base * critMul
    let mitigation = 1.0                                      // MVP 暂无防御属性，预留接口
    return floor(raw * mitigation)
```

**符号溯源**：`ATK` / `CRIT_RATE` → §1.1；`BASE_MISS_RATE = 0.05` / `CRIT_MULTIPLIER = 1.5` 配置常量。

**说明**：
- `floor` 保证整数伤害，避免 UI 显示小数
- `isCrit` 触发时如发起方为 `HERO` 且本场未触发过暴击，**额外发出 `OnFirstHeroCrit` 事件 → 触发 B07**（与 narrative B07 触发条件一致）
- `BASE_MISS_RATE` 设为 5% 而非 0：让 L03 / L04 关卡中"勇者偶尔 Miss"成为可能（levels.md L03 描述 HERO_W02 "可能触发 1 次 Miss"）

### 2.2 抚恤金扣款公式（怪物阵亡时）

```
Compensation(monster) = floor(monster.salary * COMP_DAYS_MUL + COMP_BASE)
COMP_DAYS_MUL = 3      // 按"3 天薪资"作抚恤金基数
COMP_BASE     = 5      // 最低保障金，避免低薪怪死了不痛
```

**示例**：8 薪水怪物阵亡 → 抚恤金 = 8×3+5 = **29 碎片**。L03 配置确保至少 1 怪阵亡 → 至少扣 29，配合 §4.3 触发 P03。

### 2.3 谈薪幅度公式（P02 触发）

```
NegotiateRaise(currentSalary, monsterLevel) =
    floor(currentSalary * (1 + NEGO_PCT_PER_LEVEL * monsterLevel))
NEGO_PCT_PER_LEVEL = 0.20    // 每升 1 级，谈薪要求 +20%

// 玩家选项：
//   批准 → currentSalary 立即更新为新值
//   拒绝 → 触发"消极怠工"词条：本关该怪物 ATK ×0.75，且下场战斗起 ATK ×0.85（持续 1 场）
//   <!-- v0.1.1 修订 2026-05-18：补持续 1 场后清除规则与连续拒绝时的刷新行为 -->
//   词条清除：×0.85 持续 1 场后自动清除（区别于离职，不永久影响怪物）。同关卡内连续拒绝时词条不叠加但持续场次刷新到 1。
```

**为什么 +20%？** 让 L04 谈薪在玩家"接受=经济变紧 / 拒绝=战斗变弱"间形成两难（见 levels.md L04 难度备注），20% 这一档对 8–10 薪水怪物意味着 +2 碎片/天 × 4 天 ≈ 8 碎片，与一次 B06 补贴量级相当，是有感取舍。

### 2.4 B06 战时补贴消耗 X 公式

> 落实 narrative.md / levels.md 留白。

```
B06_X(survivingCount, currentSoulShards) =
    let base   = X_BASE_PER_MONSTER * survivingCount     // X_BASE_PER_MONSTER = 8
    let scaled = min(base, floor(currentSoulShards * 0.30))
    return max(X_BASE_PER_MONSTER, scaled)
```

**填值**：以"L05 中场存活 2 怪" 为典型场景 → X = 8×2 = **16 碎片**，存活怪 HP +20%。
**为什么 16？** L05 单次战斗经济流入 ~20–25 碎片（见 §5），16 接近一次胜利收益的 70%，让"批准补贴"有真实压力而非送出选项。

### 2.5 B04 团队战斗津贴消耗 Y 公式

```
B04_Y(survivingCount) = Y_BASE * survivingCount + Y_FLAT
Y_BASE = 6     // 每存活怪 6 碎片
Y_FLAT = 5     // 行政固定支出
// 效果：我方全体 ATK +15%（本场）
```

**填值**：L05 典型 2 怪场景 → Y = 6×2+5 = **17 碎片**。
**为什么略高于 B06？** B04 触发条件为"勇者 HP > 60% 且第 3 ROUND_TICK"，即战斗仍有 ≥2 个 ROUND_TICK 可享受 +15% ATK 加成，期望额外伤害 ≈ 12×0.15×2 ≈ 3.6（约可少挨 1 次反击），价值与 B06 的"HP +20%≈12 HP"接近，加价 1 碎片体现"主动 buff > 被动救命"的微妙差。

### 2.6 P03 安全线阈值公式

```
SAFETY_LINE = avgDailySalary * SAFETY_DAYS
            = 8 * 5
            = 40
```

**符号溯源**：`avgDailySalary` = 默认怪物模板薪水中位（见 §3）；`SAFETY_DAYS = 5` 表示"剩余碎片应至少撑 5 天薪水"。
<!-- v0.1.1 修订 2026-05-18：补 avgDailySalary 取 8 而非全模板中位 9 的口径说明 -->
**口径注脚**：`avgDailySalary` 取 TANK 模板薪水 8 作锚（保守估计：玩家首招大概率 TANK），非全模板中位 9（TANK 8 / DPS 10 / RANGE 9）。如玩家招募偏向 DPS/RANGE，实际安全线压力略高，由 P03 警告自然显化。
**为什么 40？** L03 战后玩家预期账户 ≈ 启动 120 − L01 招募 25 − L02 招募 25 − 战前共 3 天薪水 24 − L03 抚恤金 29 + L02 通关奖励 20 = **37**（详见 §4.3 账户曲线表），37 < 40 安全裕度仅 3 碎片，确保 P03 在 L03 抚恤金扣款瞬间稳定触发，符合 narrative v1.3 的 "L03 抚恤金扣款后若碎片低于安全线即触发"。<!-- 主策划 Review 修订 2026-05-18：原推导漏算 L02 通关奖励 +20，与 §4.3 账户表数字不一致 -->

### 2.7 奖金（战前主动发放）

```
Bonus(level) =
    level == "small"  ? (cost: 8,  effect: targetMonster.ATK *= 1.20 本场)
  : level == "medium" ? (cost: 15, effect: targetMonster.ATK *= 1.40 本场)
  : level == "large"  ? (cost: 25, effect: targetMonster.ATK *= 1.70 本场)
```

**为什么三档？** 给玩家"小修大补"自由度；large 档单笔约等于 1 次招募成本，仅 L05/L06 高压关有动力使用。

### 2.8 扩建成本

```
ExpandCost(currentSlots) = 30 + 15 * (currentSlots - 2)
// 槽位 2→3: 30, 3→4: 45, 4→5: 60
```

**为什么递增？** 防止 L05 一次性扩张到 5 槽导致 L06 兵海碾压；递增成本让扩建必须放在中期（L03–L04）才有节奏价值。

### 3.2 怪物升级条件 & 等级加成（落实 concept 留白）

```
LevelUpRule:
  触发：战斗胜利后，存活且本场有效造成伤害的怪物自动 +1 级
  上限：5 级
  加成（按等级线性）：
    HP   = baseHP  * (1 + 0.15 * level)
```

**为什么 L04 战后都是 26？** L04 设计为「两种选择均可通关」（见 levels.md L04），账户层面两路径殊途同归：
- **批准谈薪** → 37 − 16（2 天薪）+ 30（通关奖）− 10（谈薪涨幅 4 天累计，按 +20% × 中位薪水 ≈ +2.5/天 × 4 天）= **26**
- **拒绝谈薪** → 37 − 16（2 天薪）− 15（medium 奖金，用以补强消极怠工导致 ATK 下降）+ 30（通关奖）= **26**（"消极怠工"是战斗内 ATK debuff，不直接扣碎片，只通过迫使玩家发奖金弥补战力间接扣）

两条路径账户结果对齐，但**风险结构不同**：批准路径压在"长期工资压力"（谈薪后续关卡持续多扣），拒绝路径压在"本场战力"（必须发 medium 奖金硬过 L04）。

### 4.4 L03 必死阈值实现方案（落实 levels.md 留白）

**方案选择**：**数值阈值 + 软强制**（不用脚本硬杀）

```
ForceDeathRule(L03):
  if 战斗中存在 HP < FORCE_DEATH_HP_THRESHOLD 的我方怪物
    且 当前 ROUND_TICK >= 4
    且 本场尚无怪物阵亡:
      该怪物下一次受击伤害 ×= 1.5     // 数值微推，避免叙事突兀

FORCE_DEATH_HP_THRESHOLD = 8       // 约等于 HERO_W02 1 次普攻伤害
```

**保底**：若 L03 战斗结束仍无人阵亡（理论极低概率），战后强制随机 1 怪阵亡并播报 T05 文案（脚本兜底，不写入数值公式）。
<!-- v0.1.1 修订 2026-05-18：补兜底触发概率上限，对齐 §7 Playtest 验收指标 -->
**兜底触发概率上限**：经建模估算（按自然血量阈值 HP<8 且 ROUND_TICK≥4 时受击 ×1.5 的复合条件估算），L03 至少 1 怪阵亡概率 ≥ 95%，兜底脚本实际触发率 < 5%。便于 §7 Playtest 验收「≥ 95% 概率 L03 阵亡」指标真实测量（兜底命中场次需在测试日志单独标注，不计入自然死亡样本）。
**为什么这样做？** 纯脚本强杀会让玩家觉得"被剧本陷害"；用 1.5× 受击放大让阵亡来自"看得见的战斗演算"，叙事自洽。

### 4.5 L06 行动点 +1 落实

```
ActionPoints(level) =
    level == "L06" ? ACTION_POINT_BASE + 1   // 4
                   : ACTION_POINT_BASE        // 3
```

**为什么基线 = 3？** L01 引入时 3 点可做"招募 + 扩建 + 奖金"完整循环教学；L02–L05 在 3 点下保持稀缺感；L06 给 +1 表达"决战允许玩家最后梭哈一把"（招募补员 + 扩建 + 大奖金 + 留 1 点应急）。

## 5. 经济循环

### 5.1 收支表（按主线最优路径）

| 流入 | 量级 | 触发 |

### 5.2 沉淀曲线目标

- L01–L03：**净亏损**（焦虑期，建立经济痛感）
- L04–L05：**勉强收支平衡**（玩家学会取舍后开始稳住）
- L06：**单局可亏可赚**（押注关，奖金 / 补贴 / 扩建一次性投入换取战力）

> 每场战斗采用 "**事件槽** ×3" 模型：每个 ROUND_TICK 末尾按权重抽签，命中则占用 1 个槽，3 槽用尽后本场不再触发。

| L03 | B01, B02 | B01: 60%；B02: HP < 30% 时 **100%**（条件触发） |

> 玩家方 build 分类按本作"怪物组合策略"划分（非传统职业 build）。
