## 5. 给下游阶段的交接提示

### 给美术（aiart 提示词工程师）

- **风格基调统一锚定 concept § 美术风格**：扁平企业风插画 / 莫兰迪低饱和度色盘 / 大头圆眼 / 粗描边 / 纯灰背景便于抠图。**所有角色都要有"职场感"**（工牌、西装、公文包、领带），不要走传统奇幻怪物路线。
- **必出角色**：HR 总监（疲惫眼神/工牌歪戴）、魔王 CEO（巨角西装+财报+墨镜）、格鲁巴斯·史莱姆（蓝色史莱姆穿西装）、**宵星·骷髅法师（骷髅+宽大法师袍+领带松开+书本塞包里）**——注意 v1.3 已从"奥莫斯三世"改名，按宵星出图。
- **勇者按波次强化**：L02 菜鸟勇者 → L06 精英勇者，五个梯度（HERO_W01/W02/W03/W04/HERO_ELITE）需视觉可辨，不是纯换色。
- **UI 风格"公文体"**：CEO 邮件、简历、绩效考评通知、突发卡片、结局演出均按 HR 内部备忘录视觉语言；圆形倒计时进度环为突发卡片标志元素。
- **结局演出 4 张关键画面**：E01 敲钟 + 空头期权 / E02 上市破发 / E03 勇者前台合影打卡 / E04 集体离职劳动仲裁。E01/E04 含格鲁巴斯私信彩蛋，需文本卡片样式。
- **L01 资产可极简，L06–L07 是视觉重点**，aiart 出图预算向后期倾斜。

### 给开发（Atoms / Unity）

- **核心架构**：经济循环（灵魂碎片为唯一货币）+ 战斗状态机 `BATTLE_START → ROUND_TICK → EVENT_TRIGGER → BATTLE_END` 是骨架，必须用 ScriptableObject / JSON 配资源（balance §9 已点名）。
- **公式实现为纯函数**：`BalanceFormula.Damage / Compensation / NegotiateRaise / B06_X / B04_Y / Bonus / ExpandCost`，输入输出符合 balance §2 定义；严格 int 灵魂碎片避免浮点累计误差。
- **事件抽签服务**：`EventRollService.RollPerTick(level, slotsUsed)` 实现 3 槽 + 每 ROUND_TICK 权重抽签（balance §6 表），槽位耗尽即停。
- **B07 hook**：勇者首次暴击时发 `OnFirstHeroCrit` 事件触发 B07，是战斗系统唯一的 hook 型事件，与其他 B 事件分开实现。
- **L03 必死**：用数值阈值（HP<8 且 ROUND_TICK≥4 时受击 ×1.5）+ 战后兜底脚本（< 5% 触发率），不要纯脚本硬杀。
- **L06 行动点+1**：行动点为关卡参数 `ActionPoints(level)`，不要硬编码到全局。
- **MVP 优先级提示**（来自 levels §L07 备注）：L07 中 T07/T08/T09 结局触发为 MVP 必须项，T06 过场卡片可降级为纯文字。优先保结局判定。
- **谈薪 P02 拒绝词条**：×0.85 持续 1 场后自动清除（balance §2.3），同关连续拒绝不叠加但场次刷新到 1，注意状态清理时机。
- **数值文档完整、可直接进 ScriptableObject 落表**，遇到 Playtest 难度问题先回 balance §4.4 调 `FORCE_DEATH_HP_THRESHOLD`、§7 验收指标对照，不要私改公式。
